# UX/логика операторского интерфейса — тестирование 2026-10-04 (demo.naff.flek.uz)

Кто тестировал: тестовый оператор «QA Audit Probe Op» (id 74, +998****2233) через браузер, все ключевые страницы операторского рабочего места. Тестовые данные помечены «QA TEST».

## Баги по важности

### Б1. Pending-продажа попадает в «заработок» оператора — неверная логика ЗП
- GET `/api/sales/mine/` возвращает и `pending`-продажи, а `total_share` их включает.
- UI «Мои продажи» / «Моя зарплата» показывает неподтверждённую продажу как «моя доля».
- Оператор видит деньги, которых менеджер ещё не подтвердил (и может не подтвердить).
- Фикс: в `sales/mine` фильтровать `status=confirmed` (или показывать pending отдельной строкой «в ожидании подтверждения», не включая в сумму).

### Б2. Ввод телефона без кода страны теряет цифры
- В форме продажи: ввод `907771100` в поле с плейсхолдером «+998 …» превращается в `+998 07771100` (первая 9 съедается маской).
- Оператор не заметит и сохранит продаче неверный номер клиента.
- Фикс: маска должна корректно принимать 9-значный ввод без кода (`+998 90 777 11 00`), а не обрезать ведущие цифры.

### Б3. Пункт меню «Табло» ведёт на несуществующую страницу
- Сайдбар оператора: ссылка «Табло» → `/my/tablo` — страница не существует (пустой чёрный экран, без 404, без редиректа).
- Реальная страница — `/leaderboard`. При прямом заходе на `/leaderboard` сессия иногда сбрасывается на `/login` (нестабильно).
- Фикс: поправить ссылку в `AppShell.tsx`; добавить catch-all роут 404 вместо пустого экрана.

### Б4. Пустые состояния выглядят как «сломано», загрузки — вечные
- «Табло» при первом рендере: пустое поле без надписи «нет данных» (счётчики 0). После перезагрузки данные появляются — race condition рендера.
- «Моя активность»: минуту висит «Загрузка отчёта…» без скелетона и без кнопки retry; пусто/ошибка/загрузка не различаются.
- «История заявок на выходной»: пока грузится — «…», непонятно что это.
- Фикс: skeleton-компоненты + явные empty-state тексты + retry при ошибке.

### Б5. Зарплата: пугающий «0 из 101 500 000» и абсурдные сид-данные
- Формула AND-гейтов (оба должны быть пройдены) корректна, но вид «К ВЫПЛАТЕ: 0 сум из 101,5 млн» воспринимается как «всё пропало».
- Бонус за продажи 100 000 000 при плане 10 000 000 — данные не валидируются (бонус больше выручки в 12 раз).
- Сабтайтл страницы говорит «оклад минус вычеты», а на деле показываются только бонусы — оклад nowhere.
- Фикс: расшифровка по гейтам («Attendance: 0 — гейт провален; Sales: 100M — заблокировано гейтом attendance»), валидация бонуса в админке, обновить сабтайтл.

### Б6. Смешение языков RU/UZ по всему интерфейсу
- В RU-режиме: «Ariza narxi», «ARIZA MIQDORI», «OLDINDAN TO'LOV» (калькулятор), «Notogri raqam» (активность, статусы).
- В UZ-режиме: дата «05 okt. 2026 г.» с русским «г.», «QA TEST: проверка заявки...» — ок, но системные метки русские.
- Фикс: пройтись по i18n-ключам, недостающие перевести; метки статусов брать из справочника с переводами.

### Б7. Статусы продаж в «Моей активности» — «Не определена» вместо бейджа
- В списке продаж строка «04 окт. Не определена · QA TEST Клиент …» — статус продажи рендерится текстом «Не определена» влитым в имя клиента, без цветового бейджа pending/confirmed.
- Оператор не видит, подтверждена ли продажа менеджером — ключевой для него статус.
- Фикс: выводить бейдж статуса (pending — жёлтый, confirmed — зелёный).

### Б8. Кнопка «Получить код для привязки» Telegram — нет обратной связи при успехе/ошибке
- Клик → кнопка застывает в «Загрузка…» до 10+ секунд (запрос на перегруженном сервере), потом код появляется без toast.
- Если запрос упал — юзер не узнает никогда (нет onError-сообщения).
- Код и инструкция работают корректно (появляется «/link 204920, действует 10 минут, @naffai_bot»).
- Фикс: spinner в кнопке, toast при успехе, toast с ошибкой при неудаче.

### Б9. Подача заявки на выходной: непонятный UX
- После сабмита нет toast на экране (успех виден только после скролла к истории), форма частично очищается (reason очищен, дата осталась — можно случайно продублировать).
- Фикс: toast «Заявка отправлена», очищать форму полностью.

### Б10. Смена языка/темы переключается только с частичным применением
- Клик по UZ в mid-page переключает язык глобально (хорошо), но дата-пиккеры и справочники остаются на русском («День/Месяц/Год» в date input — системные).

- Логин оператора по номеру с маской, RU/UZ/тема.
- Мои лиды: карточки, 8 статусов-кнопок, колбэк с напоминанием, фильтр по статусам.
- Начало смены (QR check-in), бейдж «ОПОЗДАНИЕ», таймер смены.

- Калькулятор рассрочки: 7 сроков, комиссии 7%…75%, математика сходится.
- Моя зарплата: гейты attendance/sales, прогресс-бары, «ПО ДНЯМ».
- Заявка на выходной: создание + история со статусом «Ожидает».
- Профиль: тема/язык/пароль/Telegram-код/QR check-in виджет.
- Уведомления: 4 тумблера подписок.

## Инфраструктурный инцидент, обнаруженный во время теста
Прод (naff.flek.uz) в момент тестирования деградировал до 500/502/timeout:
- CPU steal 80% (Lightsail burstable исчерпал кредиты) + 6+ фоновых cron-лупов с полным импортом Django каждые 1–5 мин.
- Импорт Django 40–127 с > gunicorn timeout 30с → петля смерти воркеров (80 WORKER TIMEOUT/час на проде, 3/час на демо).
- После рестарта контейнера прод отвечает 200 (10–25 с на запрос), продолжает деградировать под нагрузкой sync_sheets_leads.
- Рекомендации: `--preload` в gunicorn, `--timeout 120`, пересмотр burstable-тарифа, консолидация cron-лупов в один планировщик.
