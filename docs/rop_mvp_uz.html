1. Loyihaning maqsadi

Siz NAFF (phone-shop call-center) uchun 24/7 ishlaydigan avtonom Head-of-Sales (ROP) agentini qurayapsiz. U chatbot EMAS — siz "qanday ish?" deb so'rashingizni kutmaydi. Har kuni ertalab 07:00 da Telegramga brifing yuboradi; qimmatli lead 2 soat kutib qolsa yoki operator conv 20% tushsa — darhol push qiladi; har kuni 11:00/15:00/19:00 da sizga eslatma yuboradi; yakshanba 09:00 da haftalik scorecard beradi.

Natija 3 haftadan keyin: siz telefonni ochganda agent allaqachon aytib qo'ygan bo'ladi: "Kecha Oybek'ning 3 ta qimmatli lead'i 8 soat ushlab turildi; bugun 10:00 da u bilan narx-e'tirozi mavzusida 20 daq coaching qiling, mana skript."

Kalit qarorlar:

  • Celery YO'Q — naffAI'da hali Celery sozlanmagan. Ishlatmaymiz. Buning o'rniga mavjud docker-compose cron pattern (hot-leads-watch, morning-splitter).
  • Bitta rop-scheduler service — oltitta cron o'rniga. rop_tick har daqiqa Toshkent-local soatni tekshiradi va kerakli sub-task'ni chaqiradi.
  • apps.rop_agent — alohida microservice emas, mavjud Django ichida. Postgres/Redis/aiogram-bot allaqachon shu yerda — tekshirish, debug oson.
  • HackSoft layering: models → selectors → services → apis. ORM query faqat selectors.pyda. LLM/TG chaqiruvlari faqat services.pyda. Management command'lar services.run_*() ni chaqiradi, boshqa hech narsa.

7. Avtonomlik mexanizmlari

7.1 OODA loop — har sub-task shu bosqichlarni bosib o'tadi

OBSERVE → ANALYZE → DECIDE → ACT → LEARN DB pull → LLM summ. → rule+LLM → TG push → state save

7.2 Scheduler (docker-compose, Celery YO'Q)

rop-scheduler:
  build: ./backend
  env_file: .env
  depends_on: [db]
  command: bash -c '
    while :; do
      python manage.py rop_tick 2>&1 | tee -a /tmp/rop.log || echo "rop_tick rc=$$?"
      sleep 60
    done'

rop_tick har daqiqa Toshkent-local soatni tekshiradi:

  • 07:00 → rop_morning_briefing
  • 14:00 → rop_midday_pulse
  • 21:00 → rop_evening_wrap
  • 11:00 / 15:00 / 19:00 → rop_reminder
  • yakshanba 09:00 → rop_weekly_scorecard
  • Har 10 daq (minute % 10 == 0) → rop_alert_check
  • Har 15 daq (minute % 15 == 0) → rop_cleanup_approvals

7.3 State va memory

Takrorlanmaslik — avtonom agent uchun eng muhim xususiyat.

  • Postgres (uzoq xotira): DailyBriefing (90 kun oxirgi brifing), AlertLog (barcha alert history), OperatorCoachingLog (per-op coaching), PendingApproval (24h expire).
  • Redis (qisqa xotira): alert:<code> SETNX bilan rate-limit, rop:briefing_sent:today ikki marta yuborishni to'xtatadi.
  • ROPState singleton: muted_until, last_briefing_at, last_pulse_at, last_evening_at, last_weekly_at.

7.4 Approval flow (faqat prod)

  • ROP_APPROVAL_REQUIRED=true (prod default) → har write-action PendingApproval yaratadi + inline button bilan push.
  • Owner tasdiqlaganda: aiogram rop_handlers.cb_rop_approve → services.execute_pending_approval.
  • 24h ichida javob kelmasa → EXPIRED (har 15 daq rop_cleanup_approvals ko'rib chiqadi).
  • Demo (demo.naff.flek.uz) → ROP_APPROVAL_REQUIRED=false, agent avtomatik bajaradi.

7.5 Mute (sukut)

Inline-button [⏸ Sukut 2h] → services.mute() → ROPState.muted_until = now + 2h. Har sub-task _is_muted() tekshiradi. 🔴 RED alert'lar sukutni buzadi, qolgani pauza.

10. 3-haftalik roadmap

Hafta 1 — foundations (dush-juma)

  1. Dush: apps.rop_agent skelet + 5 model + migratsiya (local SQLite'da test)
  2. Sesh: Settings/env — ROP_* block + pyproject.toml openai dep
  3. Chor: 10 ta KPI selector + 3 unit test
  4. Pay: 10 ta alert trigger + dedup via AlertLog.dedup_key + 3 unit test
  5. Jum: rop_tick scheduler + 7 ta management command (skelet)

Hafta 2 — services, LLM, TG, approval

  1. Dush: llm.py (GLM / OpenAI-compatible) + stub fallback + routing
  2. Sesh: telegram.py — send_to_owner httpx sync + inline keyboards
  3. Chor: services.py — morning/midday/evening/reminder/alert_check
  4. Pay: PendingApproval flow + aiogram rop_handlers.py
  5. Jum: Prompts (NAFF context, "hamkor = payment channel" qoidasi) + integration test

Hafta 3 — demo deploy, tune, prod cutover

  1. Dush: docker-compose.prod.yml + rop-scheduler + demo-rop-scheduler + .env.example
  2. Sesh: Deploy feat/rop-agent → demo.naff.flek.uz, ROP_ENABLED=true, ROP_APPROVAL_REQUIRED=false
  3. Chor-Pay: Live kuzatish demo'da — brifinglar, alert'lar, dedup to'g'ri ishlayaptimi
  4. Jum: Prompt tune (brifing uzunligi, UZ tilining aniqligi), model routing (glm-4 vs glm-4-plus)
  5. Keyingi dushanba: Prod cutover — ROP_ENABLED=true, ROP_APPROVAL_REQUIRED=true
